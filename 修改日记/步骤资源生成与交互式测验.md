# 学习步骤资源生成 + 交互式测验 + 评估集成 - 修改日记

## 修改日期
2026-06-01

## 修改思路

### 核心目标
在学习路径页面中，每个步骤节点可点击生成AI学习资料。普通步骤调用文档生成智能体，最后一个步骤调用题库生成智能体。资源只生成一次后缓存，最后一步为可交互答题测验，答题结果自动写入评估模块统计。

### 架构设计决策

1. **复用现有资源生成流水线**：不新建生成逻辑，而是包装现有的 `POST /resource/generate` → `ResourceAsyncExecutor` → `AgentStrategyFactory` 流水线。新增的 `generateStepResource` 端点本质上是一个"检查缓存 + 代理调用"的 wrapper。

2. **步骤类型判断**：通过 `sort` 字段最大值判断最后一步（测验），而非依赖 `path.totalStep`，因为路径调整可能导致 totalStep 变化。

3. **评估集成零改动**：`submitQuiz` 直接写入 `question_answer_record` 表，而现有的 `LearningEvaluateServiceImpl.getStats()` 已经按 userId 查询该表计算 `totalQuiz` 和 `avgScore`，无需修改评估模块。

## 难点分析

### 难点1：资源缓存判断
**问题**：如何判断步骤是否已生成过资源？
**方案**：利用 `LearningPathStep.resourceIds` 字段（已有）。生成完成后将资源ID追加到该字段，下次检查时若非空则直接返回缓存资源。

### 难点2：异步生成 + 轮询进度
**问题**：资源生成是异步的（AI调用耗时），前端需要等待完成。
**方案**：后端返回 `taskId`，前端复用现有的轮询机制（每2秒查询 `GET /resource/generate/progress/{taskId}`），完成后获取 resourceId 并调用 `linkResourceToStep` 关联到步骤。

### 难点3：题库解析兼容性
**问题**：AI生成的题库可能是纯JSON、Markdown代码块中的JSON、或纯文本格式。
**方案**：`parseQuizContent` 方法按优先级尝试：直接JSON解析 → 提取代码块中的JSON → 返回空数组。前端和后端都实现了该解析逻辑。

### 难点4：答题状态管理
**问题**：测验需要两阶段UI（答题/结果），答题阶段不能显示答案。
**方案**：前端用 `quizPhase` ref 控制阶段切换。答题阶段只显示选项卡片，提交后调用后端 `submitQuiz` 获取评分，切换到结果阶段显示答案和解析。

## 数据流图

```
点击步骤 → PathStepView.onStepClick()
  ↓
路由跳转 → /path/step/:stepId/resource
  ↓
StepResourceView.onMounted()
  ↓
POST /learning-path/step/{stepId}/generate-resource
  ↓
后端检查 resourceIds →
  ├─ 有缓存 → 返回 { status: "cached", resource }
  └─ 无缓存 → 查找智能体 → createGenerateTask → 返回 { status: "generating", taskId }
      ↓
前端轮询 GET /resource/generate/progress/{taskId}
      ↓ (status: "success")
GET /resource/detail/{resourceId} → 展示资源
POST /learning-path/step/{stepId}/link-resource/{resourceId} → 缓存关联

--- 测验流程（最后一步）---
展示题目 → 用户选择答案 →
POST /learning-path/step/{stepId}/submit-quiz
  ↓
后端解析题库JSON → 比对答案 → 写入 question_answer_record → 返回分数
  ↓
前端展示结果（正确/错误标记 + 解析）
  ↓
评估模块自动统计（getStats读取question_answer_record）
```
